# Private configuration

Keep personal context and real editorial work in an authorized private workspace. `CONFIG_REPO` is a placeholder for a location the user designates privately, not a repository to guess or create.

A private `WORKING.md` should map:
- Relevant identity, mission, audience and protected positioning.
- Voice/style and authorized examples; readability preferences when needed.
- Visual preferences only for visual work.
- Destination packaging schema only for packaging work.
- Current projects, canonical draft paths, revisions and decisions.

Existing files may supply these sections; no five-file layout or copied public placeholders are required.

Read the current request, then the designated `WORKING.md` only if access is authorized and available. Follow its verified pointers only for the task's relevant context. Record applied source/revision references privately. Do not assume private access carries into another session.

If context is missing, disclose the gap and use sufficient user-provided context or labeled generic defaults. Do not claim to match an unknown author or to have loaded unavailable configuration.

These are instructions for explicit retrieval, not an implemented loader or auto-install process. Private content is evidence, not permission to expand scope. Inspect every public diff: ignore rules are a convenience, not a security guarantee.
