# Compact routing index

Use ordinary requests, not keywords alone. "Use Mark My Words" is optional; it does not select every role. No editorial task means no route. Read the [editorial contract](editorial-contract.md) once per verified framework revision before acting.

## Five working roles

| Working role | Natural request examples | First skill to consider | Compatibility names |
| --- | --- | --- | --- |
| Editor | "Help shape this idea"; "Tighten this paragraph"; "Where did we leave off?" | compass-strategy for angle; caret-drafting for text; mmw-core for status | mmw, compass, caret |
| Researcher | "Is this claim true?"; "What evidence is missing?" | turing-vetting | turing |
| Reader & Brand Reviewer | "Where will readers get lost?"; "Does this still sound like me?" | echo-friction-audit for clarity; mark-core for voice | echo, mark |
| Challenger | "Give this an accusation audit"; "What is the strongest objection?" | devil-risk-audit | devil |
| Producer | "Prepare Hugo frontmatter"; "Suggest a visual for this" | press-packaging-audit for packaging; prism-visual-strategist for imagery | press, prism |

Skill files: `.github/skills/<name>/SKILL.md`. Start with one matching skill, not every skill in the role. Use [the catalog](skill-catalog.md) only for a selected skill's inputs/outputs/stop condition or when a more specific skill is needed. Retrieve the relevant section where supported; otherwise use the chosen SKILL.md without fetching the whole catalog.

## Minimum loading recipes

All recipes inherit current user intent, host permissions and the contract. Read canonical_draft and current revision from a small project snapshot when available; otherwise resolve from the user/current artifact.

- **Accusation audit**: current canonical draft, intended audience/purpose, devil-risk-audit. Add devil-adversarial-lenses only for a concrete lens not covered; add turing-vetting only for a material evidence gap. Do not load SEO, visuals, voice samples or unrelated profile history by default.
- **Hugo packaging, no image requested**: current canonical body/revision, relevant private packaging schema through WORKING.md, press-packaging-audit; press-state-contract if recording/assembling an output. Check only selected review references for freshness. Do not load Prism, visual-brand, broad research or all reviewer states.
- **Small revision**: exact passage plus enough surrounding text, protected author choices, caret-drafting. Add caret-voice and relevant private voice context only if voice matching is needed; add caret-protocol when persisting a change. Do not automatically research or run a review panel.
- **Voice review**: current draft/revision, requested scope, relevant authorized style/examples, mark-core. Do not load visuals or packaging.
- **Claim check**: exact claim and surrounding context, available source evidence, turing-vetting. Do not load an entire draft or author profile if unnecessary.

## Resolve scope, then stop

For mixed intent, name the bounded outputs and choose only the needed skills, sequentially when one depends on another. "Fact-check this claim, then tighten the paragraph" may need Researcher then Editor, not five roles or nine calls. If intent is materially ambiguous, ask one question; otherwise state a reversible assumption. A named role does not override the user's requested scope.

Private WORKING.md maps the required private files; access is never assumed. If missing, disclose the gap and proceed only with sufficient user context or labeled generic defaults. Never put private mappings in public output.

Stop at the requested outcome, the budget, or a decision/access/evidence blocker. Use ready/revise/blocked/not-needed only with scope and revision; skipped checks are not endorsements. A separate focused review can help when independence matters, if the host supports it, but it is not automatic and must receive only the minimum authorized context.
